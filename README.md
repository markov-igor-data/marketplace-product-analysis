# Анализ продуктовых метрик маркетплейса (Product Analytics)

Данный проект выполнен в рамках финального модуля курса по Data Analytics (Академия Карпова). Оценка преподавателя: 40/42.

## 🎯 Цель проекта
Провести комплексный анализ данных маркетплейса, выявить причины стагнации выручки и низкого удержания клиентов (Retention), а также предложить бизнес-решения для роста продукта.

## 🛠 Стек технологий и инструменты
*   **Язык программирования:** Python
*   **Библиотеки для анализа и визуализации:** Pandas, NumPy, Matplotlib, Seaborn
*   **Среда разработки:** Jupyter Notebook
*   **Инструменты:** Git

## 📊 Выполненные задачи (Что было сделано)
1.  **Предобработка данных:** Очистка датасета, обработка пропусков и аномалий. Объединение таблиц (`merge`) для расчета выручки по каждому заказу.
2.  **Когортный анализ (Cohort Analysis):** Построение матрицы удержания (Retention) по когортам клиентов и визуализация результатов с помощью тепловой карты (`heatmap`).
3.  **Анализ транзакционной активности:** Расчет ключевых продуктовых метрик — GMV (объем продаж), MAU (активные пользователи), ARPU (средняя выручка на пользователя). Анализ частоты покупок (доля клиентов с повторными заказами).
4.  **Приоритизация гипотез:** Формулировка трех продуктовых гипотез для улучшения метрик и их оценка с помощью фреймворка **ICE** (Impact, Confidence, Ease).
5.  **Дизайн A/B-теста:** Для выбранной гипотезы спроектирована система метрик: целевая (доля доставленных заказов), прокси-метрика (скорость перехода в статус «в обработке») и guardrail-метрика (средний чек).
6.  **Бизнес-отчет:** Подготовлен отчет для Product-менеджера с формулировкой проблемы, выводами и рекомендациями по развитию продукта.

## 💡 Ключевые выводы и результаты
В ходе анализа было выявлено, что клиенты быстро «остывают»: медианный Retention 1-го месяца составил всего **0.51%**, а доля клиентов с повторными покупками — **3%**. 
Основная проблема продукта — клиенты совершают одну покупку и уходят, из-за чего бизнес тратит ресурсы на привлечение без возврата инвестиций.

**Предложенное решение:** 
С помощью фреймворка ICE была выбрана самая приоритетная гипотеза — *«Исправить баг в системе процессинга заказов»* (наивысший показатель Impact при высокой уверенности и легкости внедрения). Исправление бага должно снизить количество отмен и положительно повлиять на удержание пользователей.
